# Markdown preview — Code / Preview sub-toggle

GitKraken detects Markdown files (`.md`, `.markdown`) and exposes a
Code / Preview sub-toggle inside the File View. Preview renders via a
unified / remark / rehype pipeline — the same toolchain used by
`react-markdown`.

## Sub-toggle enum

```js
FileViewMode = { CODE: "CODE", PREVIEW: "PREVIEW" }
```

This is **separate** from `fileDisplayModes` (doc 02). It only applies
when a Markdown file is open and the outer view is File View (not Diff
View). Diff mode always shows raw Markdown source as text-diff; there
is no "preview diff" feature.

## Toggle UI

Two buttons in the Markdown-only sub-toolbar:

| Caption key                           | Value      | Checked when          | `data-testid`       |
|---------------------------------------|------------|-----------------------|---------------------|
| `FileViewPanel-FileViewCode`          | "Code"     | `mode === CODE`       | `markdown-code`     |
| `FileViewPanel-FileViewPreview`       | "Preview"  | `mode === PREVIEW`    | `markdown-preview`  |

Only surfaces when `getIsMarkdownFile(filePath)` returns true.

Detection uses file extension — `.md`, `.markdown`, `.mdx` are all
routed to the same preview renderer.

## Rendering pipeline

GitKraken uses `react-markdown` verbatim. Internals (abbreviated from
the bundle):

```js
function buildProcessor(props) {
  const rehypePlugins = props.rehypePlugins || [];
  const remarkPlugins = props.remarkPlugins || [];
  const remarkRehypeOptions = {...props.remarkRehypeOptions, ...defaultOptions};
  return unified()
    .use(remarkParse)
    .use(remarkPlugins)
    .use(remarkRehype, remarkRehypeOptions)
    .use(rehypePlugins);
}
```

Standard `react-markdown` 8.x pipeline.

## Link security

Observed string:

```
MarkdownLink-FileOutsideRepository = "GitKraken blocked opening this link because it tried to access a file on your machine outside of the repository."
```

Markdown links with `file://` or relative paths escaping the repo root
are **blocked** with this warning. Security hardening — prevents a
malicious README from opening arbitrary local files.

Implementation: the link-click handler resolves the target path, checks
containment against the repo root, and rejects if outside.

`http://` / `https://` links open in the user's default browser (via
Electron `shell.openExternal`, in Tauri equivalent is `tauri::api::shell::open`).

## Scroll / anchor behavior

Heading anchors (`#heading-slug`) generated by `remark-rehype` default
`#` prefix + kebab-case slug. Click on an in-preview link to a heading
scrolls to that heading within the preview pane — no route change.

## Yryvu implications

- **Use `solid-markdown`** (Solid port of `react-markdown`) — keeps the
  same unified/remark/rehype pipeline, just Solid components.
- **Same plugin set** as GitKraken for feature parity: remark-gfm,
  remark-breaks, rehype-sanitize (or rehype-raw with sanitizer),
  rehype-highlight or rehype-prism.
- **Implement the link-outside-repo block** identically — security
  parity is non-negotiable.
- **Binary Code/Preview toggle**, no side-by-side.
- **Detect markdown by extension** — `.md`, `.markdown`, `.mdx`.
